# DSH Novel Studio

本地小说创作工作台：作者主导的 Writer 与有范围、有预算、有检查点的 Director，共享同一本作品、正文版本与事实状态。

当前版本 **0.2.0**：在可用 V1 上完成文风、文本管线、长篇记忆和提示词分层升级。原始 V1 A–L 和本轮 A–H 分别保留验收记录。56 项自动测试、真实 DSH 模型、浏览器操作与重启读回通过；开发期间的失败和过期产物保留在 [验收记录](docs/novel-studio/ACCEPTANCE.md) 中。

- Writer：CodeMirror 正文、自动保存与失败重试、撤销重做、选区 AI、Diff 与部分采用、版本恢复、专注布局。
- Director：开书方向、有限章节创作、审校修复、未来重规划、资料抽取和剧情推演；任务约定、预算、事件、产物与恢复持久化。
- 共享资料：分层大纲、人物树与关系图、世界树、时间线、伏笔、事实来源、灵感、导入导出和完整项目备份。
- 人机交接：查看不终止任务；接管保护作者版本，旧调用只能成为过期产物；重新委派从新正文重建状态。
- 创作配置：预设兼容报告与适配 Diff、原创文风组合、全局/项目/任务覆盖、固定配置版本、三阶段可追溯正则。
- 长篇记忆：已接受正文的证据摘要、封存段与覆盖缺口；按章和知情范围读取关系/世界、按别名召回早期细节、改文失效重建。
- 生成检查器：实际调用的分层/角色/宏/变换/版本与相邻请求 Diff；本地复用和服务端缓存计量分开。

## 在 DSH 中运行

需要 Node.js 24.14 或更新版本，以及已配置模型的 DSH 0.1.5-rc.1。当前开发目录为 `C:\Users\rgywd\Documents\novel`。

```powershell
cd C:\Users\rgywd\Documents\novel
npm ci
npm run build
```

首次安装到独立的 DSH 配置（本机已完成）：

```powershell
dsh --profile novel-studio --from-default-profile web --dump-config | Out-Null
dsh plugin --profile novel-studio add C:\Users\rgywd\Documents\novel
```

启动：

```powershell
npm run start:dsh
```

打开 [DSH Novel Studio](http://127.0.0.1:4318/novel-studio/)。模型连接和凭据由 DSH 管理，在 DSH 的 Models 设置中选择模型。任务的“均衡创作”优先使用模型公开支持的非推理模式，否则使用低推理档；也可以按任务沿用 DSH 配置。实际调用配置和 token 用量会进入步骤记录。

修改代码后：

```powershell
npm run build
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/serve.ps1 -Dsh -Restart
```

服务重启会将中断任务保留为暂停状态。打开任务后选择恢复；作品已变化时，选择重新委派。

## 独立写作与演示

```powershell
npm run build
npm start
```

打开 [本地写作实例](http://127.0.0.1:4317/novel-studio/)。此入口支持离线编辑、导入、备份和显式演示模型，真实模型需要通过 DSH 插件入口使用。

两个运行实例默认使用不同的 SQLite 文件，避免两个服务同时写一个库。每个实例内 Writer 与 Director 共享作品。推荐日常使用 DSH 入口。

## 使用本轮升级

1. 在现有作品左侧打开“创作配置”。选择“克制叙述”“快节奏冒险”或“对白驱动”，也可上传 Chat Completion JSON。先看兼容报告，保存版本后再应用到当前作品；导入本身不会启用。
2. 若使用 `{{char}}`、`{{user}}`，分别绑定角色和作者称呼；视角人物另行选择。未知宏保留并报警。在“正则测试”查看输入、命中、Diff、耗时与单规则开关，再保存规则版本。启用“接受章节后维护长篇记忆”。
3. 打开“生成检查器”，展开编译预览核对有效来源、P0–P5、角色与资料；预览不调用模型。运行中的任务固定配置，新设置用于下一任务。
4. 在 Director 生成并接受第一章，查看真实步骤和记忆更新。进入 Writer 仅查看不会中断任务；点击接管、改正文、确认保存后，旧摘要和依赖立即失效。
5. 重新委派下一章，运行器先同步作者新正文，再创作。用“作品记忆”搜索早期姓名、物品和线索并跳转原文；用步骤中的“检查生成请求”核对最终发送的版本、处理结果和实际缓存字段。

本机“潮痕档案 · 升级真实验收”已完成真实的第一章935字 → 作者将钥匙交还 → 第二章1025字，第二章请求引用作者新版本。作品中另有一个独立的短文风输入章，故记忆显示2/3覆盖；三份风格输出保持未接受，不冒充主线章节。[三种完整文风样本与读稿说明](docs/novel-studio/evidence/upgrade-style-samples.md) 可直接阅读。

实际浏览器还使用 `test/fixtures/upgrade-preset.json` 和 `upgrade-world.json` 完成上传、适配、正则错误、关系历史和双模式操作。它们是原创测试样例，不代表全部社区预设兼容。

## 从第一章到下一章

1. 在书架选择“我有一个灵感”，填写作品名与一句前提；已有小说选择 TXT/Markdown 导入。
2. 在 Director 选择“从灵感开书”，填写目标，检查自动接受与预算，然后执行。
3. 选择“创作章节”，填写目标字数与禁区。真实草稿、审校、状态提交会依次出现在任务中。
4. 从成果跳到 Writer，点击“接管并编辑”。修改正文后检查“已保存”和修订号。
5. 再到 Director 委派下一章。运行器先从作者最新正文重建状态，再构建下一章上下文。
6. 在成果的“资料依据”查看所用正文版本、来源和省略原因；重大问题会暂停并展示可处理的审查成果。

本机已有“纸灯与归信 · 真实 AI 验收”的成功作品：修订 12，四章正文。可直接查看第二章任务的资料依据及两章 4000 字任务。另一个同名早期验收作品保留了预算耗尽的暂停记录；成功作品 ID 为 `project_08a514b1-1198-4741-9ac0-836da5d3764d`。

书架的原创演示会新建独立示例作品，可重复创建。演示内容明确标注为固定测试样本，不能用来判断真实 AI 的创作质量。

## 保存与迁移

- DSH 实例：`.local/dsh-novel-studio.sqlite`。
- 独立实例：`.local/novel-studio.sqlite`。
- “导入、导出与备份”支持 UTF-8 / GB18030 TXT 和 Markdown、拆分预览、原文保留、正文导出和带校验和的完整 JSON 备份。
- 数据库 schema 1→2 为增量迁移，不重写旧作品。新配置默认关闭；没有配置快照的旧任务保留旧行为。
- 恢复 schema 1 或 2 备份会创建独立副本，保留正文版本、设定、来源、任务、配置原文件与祖先版本、记忆历史。恢复有效配置只绑定新作品，不改变全局默认；旧请求明确标为历史。
- 本次升级前的8份备份位于 `.local/backups/upgrade-20260913/`。解除升级故障可在“导入、导出与备份”恢复为副本；不要将新 schema 数据库直接交给旧代码，或在线覆盖数据库文件。
- 运行中的数据库请通过应用备份。手工复制 SQLite 文件应先停止对应服务。
- 本地日志在 `.local/`，不进入 Git。DSH 日志可能含本地 Web 访问令牌，请勿分享未经处理的日志。

## 验证

```powershell
npm run typecheck
npm run build
npm run test:unit
npm run test:integration
npm run test:e2e
# 以下只读检查依赖本机保留的验收作品与备份：
npm run test:old-projects
node scripts/upgrade-final.mjs
# 以下会调用真实模型；日常查看成果无需重跑：
npm run smoke:upgrade
```

`smoke:upgrade` 在独立原创作品中验证预设、正文处理、接管、记忆、提取和文风样本；`smoke:real` 是历史 V1 开书和有限连续创作验收。它们会调用已配置的 DSH 模型，失败时保留作品、草稿与回执。对应命令加 `-- --continue` 才从已有断点继续，总任务预算不会自动增加。升级烟雾的最终 PASS 还要求人工读稿证据与当前样本哈希匹配，脚本不会仅凭输出不同宣称风格有效。

证据保存在 `docs/novel-studio/evidence/`。浏览器检查通过实际运行的前端完成，与确定性提供方测试及真实模型验证分别记录。

当前结果：11 单元 + 43 集成 + 2 确定性 HTTP E2E 全部通过；类型检查、构建通过。8/8旧作品哈希未变，最终重启后10/10项目的完整备份校验和一致。实际浏览器桌面/390窄窗口、深浅主题与11张截图通过。真实 `deepseek-official / deepseek-flash` 完成升级闭环、中性总结/抽取和三种文风对照；27次返回缓存字段，17次读量大于0，单次0–4480 token，写入量 UNKNOWN。这包含失败和重试，不是固定负载的缓存命中率基准。

## 已知边界

- 当前验证环境是 Windows、Node 24.14、DSH 0.1.5-rc.1；其他 DSH 版本及模型供应商尚未验收。
- 兼容的是明确列出的预设/World Info 子集；高级聊天深度、脚本、TC/Instruct/Context 模板和 DSH 未公开的采样参数不执行，保留原文和报告。完整 [兼容矩阵](docs/novel-studio/ARCHITECTURE.md) 区分 SUPPORTED / PARTIAL / UNSUPPORTED。
- 宏无任意表达式求值或变量写入。正则每条最多500ms、1000次匹配、10万输入字符；超限在可终止 Worker 中失败。展示规则不进入事实和后续模型上下文。
- 关系按章节与显式时间标签查询，不自动给任意相对时间文字排序。世界递归深度最多2、普通条目最多24；必要规则放不下则暂停。记忆没有覆盖的正文不会被当成已经处理。
- 请求检查器保存最近100次本地可观察调用；不是下游 HTTP 抓包。缓存读写未知保持 UNKNOWN，不支持跨厂商缓存对象、TTL或费用估算。
- 每个任务最多 3 章、每章最多 2 轮自动修复。项目修改采用保守的依赖失效策略，可能需要重新委派；不会静默放大预算。
- 字数按汉字、Latin 单词和数字计数，不计标点和空白。低于目标 60% 阻塞接受，75%–135% 为建议范围；不会重复或截断文本凑数。
- 上下文以字符控制预算（默认 18,000，上限 48,000），不是精确 tokenizer 计数。单章超过抽取预算时需在拆分预览中继续分段。导入上限 500 万字符，每段上限 10 万字符。
- 抽取结果保持待确认；跨章同名候选需要作者绑定到正式实体，不自动假定是同一人。关系图同时显示前 30 位角色，其他角色在人物树中查找。
- 一致性工具提供证据、确定性约束和 AI 风险判断，不能证明文学质量或保证没有设定冲突。真实模型验收包含修复后续跑，首次尝试全部成功的可靠性尚未做统计。
- 文风仍需读稿。本轮最终人称/句式差异可观察，但冒险伴写样本567字低于800字要求，保留为未接受建议；真实整章935/1025字另行验收。初期人称失败、抽取引文失败和预算暂停均保留。
- 仅在本机运行，不自动发布。模型费用不编造金额，只记录可信 token 回执或保守预留。
