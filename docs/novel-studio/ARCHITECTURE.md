# Architecture

`src/domain.ts` is the shared mutation boundary. `src/store.ts` owns SQLite and transactions. `src/context.ts` produces bounded packs with trace. `src/review.ts` handles evidence validation and deterministic constraints. `src/runtime.ts` owns a bounded durable state machine. `src/prompts.ts` owns versioned semantic contracts. `src/provider.ts` is the DSH model adapter plus explicitly labeled deterministic testing provider. `src/http.ts` transports the same operations used by registered DSH tools. `src/plugin.ts` mounts the whole workbench in DSH; `src/server.ts` starts an independent loopback workbench without credentials for offline writing/testing. `src/ui/` contains the two views of the same data.

SQLite stores projects, structured objects, immutable body versions, tasks/steps/artifacts/events and changesets. Per-project story revision is deliberately conservative: material edits invalidate outstanding shared-state tasks. Chapter revisions additionally bind proposals and autosave. Accepted chapter and derived facts are one transaction; a unique commit key provides idempotency. Canonical data is SQLite for this new product; existing DSH Markdown books are not silently imported or rewritten.

DSH exposes full-page web routes and a model stream but the inspected writing plugin has no reusable persistent director. The Novel runner is domain-specific and lives inside the plugin host process. The DSH Core remains unchanged. Model credentials remain inside DSH. No external provider is silently selected. Original import text is retained verbatim in the database; backup is versioned JSON with integrity checksum and restores as an independent copy.

Recovery favors a visible PAUSED state after server restart, preserving completed steps/outputs. Resume reuses identical-input steps. Project edits require an explicit fresh delegation/rebase; old generations remain stale artifacts. Structural facts use exact source quotes and provenance; subjective semantic judgments remain AI risks, not proof of literary quality.

Structured prompts include JSON Schema generated from the actual Zod 3 contracts using pinned `zod-to-json-schema` 3.24.6. Validation errors include field paths and are returned on at most two retries. The adapter records each call's actual tokens, selected model route and effort, or conservative reserved usage when no trustworthy receipt exists. Balanced tasks use an advertised `off` effort, otherwise advertised `low`; choosing configured keeps the DSH model setting. The host selection object is never mutated. No fallback provider is silently used.

Accepted-state refresh has a separate context purpose: it reads the author's current text, formal earlier facts and rules, excluding superseded chapter plans and the next task's restrictions. AI blocking findings become a `state-review` artifact. An author can record an intentional-arrangement decision and accept a state refresh without rewriting the body or incrementing the new-chapter counter. Structured hard conflicts remain non-ignorable. Hand-edited working drafts are durably included in a new review task and cannot be accepted until reviewed.

Metadata APIs reject chapter body/status/version projection changes. Authored changes to a sourced fact create a replacement user fact with a supersedes reference; the old value/source remain immutable and revoked. Chapter rollback does not revive a fact that the author has explicitly superseded. Context projects the latest effective value per entity/property/narrative modality, with historical records still inspectable. Accepted extraction siblings are rebased only when their source chapter versions are unchanged.
